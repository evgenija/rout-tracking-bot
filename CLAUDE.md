# CLAUDE.md — правила роботи з цим проєктом

## Проєкт
Route tracking + фінансова модель (P&L) для логістичної компанії.
- **P1** — трекінг маршрутів водіїв (tracking, geo, ping, scheduler)
- **P2** — фінансова модель: виручка, Op.Profit, Net Profit, беззбитковість

## Деплой
- Бот активний вдень. **Push тільки після 20:00 Київ** якщо деплой зупиняє бота.
- `git push` — тільки після явного «пушимо» від Жені.

## Правила змін
- Жодних змін у P1 коді коли задача стосується P2, і навпаки.
- Жодних змін коду без явного «виправляй» від Жені.
- Жодного `git push` без явного «пушимо» від Жені.
- HIGH risk зміни → окремий апрув перед виконанням.

## Чек-ліст перед будь-якою зміною коду

### 1. Знайди всіх «сусідів»
```bash
grep -rn "назва_функції\|НазваКласу" . --include="*.py"
```
- Знайди ВСІ місця де використовується функція або клас що змінюється
- Окремо знайди тести де вона мокується або конструюється напряму
- Якщо мок не відповідає новій сигнатурі — оновити мок і пояснити чому

### 2. Перевір формулу числом (якщо є підрахунок або агрегація)
- Побудуй конкретний числовий приклад end-to-end
- Переконайся: значення на вході = значення на виході після агрегації
- Якщо є «сума за діапазон» і «читання по одному дню» — явно перевір що
  читання повертає денне значення (`сума / кількість_днів`), а не суму цілком

### 3. Перевір edge cases для batch/діапазонів дат
- Що трапляється якщо дати не суміжні (є пропуск всередині)?
- Чи є constraint у БД що може заблокувати запис (overlap, unique)?
- Кнопки/дії формуються для кожного суміжного блоку окремо?

### 4. Після кожної зміни — тести і імпорти
```bash
python3 -m pytest tests/unit/ -v --tb=short
python3 -c "import bot.handlers.змінений_модуль; print('OK')"
```
- Якщо тест зламався — виправити і пояснити чому
- Показати git diff перед кожним файлом що змінюється

## Кінець кожної сесії

Перед тим як сесія завершується (після деплою або після останньої задачі):
1. **Підсумок** — що зроблено, які баги знайдено по дорозі, що спрацювало добре
2. **Корегування промптів** — якщо промпт у Notion містив неточності або пропуски, запропонувати що виправити
3. **Оновлення CLAUDE.md** — запропонувати що додати на основі нових знань з сесії (нові edge cases, нові правила, нові перевірки)
4. Узгодити з Женею і внести зміни тільки після підтвердження

## Структура тестів
- `tests/unit/` — unit тести, запускати завжди
- `tests/smoke_test.py` — викликає `sys.exit()` при імпорті, не запускати через `tests/` напряму

## Таблиці P2
- `period_input` — виручка + sales_km; підтримує діапазони (date_from, date_to)
- `daily_input` — дані доставки по водіях
- `coefficients` — коефіцієнти (margin_pct, monthly_shared, monthly_taxes, revenue_median_2025 та ін.)

## P2 daily_input — можливі дублі
`on_route_finished()` робить plain INSERT без ON CONFLICT.
При подвійному натисканні "Фініш" — виникають 2 записи в `daily_input` з різними km (перший сегмент і повний маршрут).
Перед аналізом будь-якого маршруту завжди перевіряти:
```sql
SELECT route_id, COUNT(*), SUM(km), SUM(logistics_cost)
FROM daily_input
GROUP BY route_id HAVING COUNT(*) > 1;
```
Якщо дублі є — злити вручну в один запис з правильним km і тарифом.
